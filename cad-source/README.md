# CAD Source — 49 Balls Head Road (exact vector plans for the 3D model)

Spun off from the Horizon Homes **Rev U** DWG construction set (converted DWG → DXF).
This is the **exact-coordinate** source for the house geometry: every wall, window and
door is real vector data on named layers, so you can read dimensions **to the millimetre**
instead of eyeballing them off PDF renders.

## Why this exists

The `House/` Three.js model was built from the Rev S **PDF** sheets, which meant reading
dimension chains by eye (≈±0.5 m drift on long chains). These DXFs remove that guesswork:
pull coordinates straight from the CAD.

> **Revision caveat:** these are **Rev U (17-04-2026)** — *newer* than the Rev S set
> (27-01-2026) the House model was built from. The shell dimensions are near-identical, but
> the window schedule / minor amendments may differ. Reconcile deliberately before adopting;
> don't blind-swap. Details in `cad-metadata.json` → `note_revision`.

## What's here

- `dxf/` — 14 sheets: 3 floor plans + site, 4 elevations, 5 sections, details.
- `windows_doors.csv` / `.json` — extracted window+door schedule (exact mm position,
  rotation, decoded W×H, product code) for the A-GLAZ/A-DOOR block instances.
- `cad-metadata.json` — levels/RLs, wall thicknesses, layer legend, size-code decoding,
  and the coordinate-mapping hint.

## Reading geometry (ezdxf)

```python
import ezdxf
doc = ezdxf.readfile("dxf/plan_lower_ground.dxf")
for e in doc.modelspace():
    if e.dxf.layer == "A-WALL" and e.dxftype() == "LINE":
        print(e.dxf.start, e.dxf.end)   # exact mm, architect world coords
```

## Layer legend (the ones that matter)

| Layer | What |
|---|---|
| `A-WALL` | external walls (LINE/ARC) |
| `I-WALL` | internal partition walls |
| `A-COLS` | columns / posts (alfresco, porch, balcony) |
| `A-GLAZ` | window blocks — block name carries the size code |
| `A-GLAZ-IDEN` | window tags `W1..W26` + code text |
| `A-GLAZ-CURT` / `-CWMG` | curtain-wall / feature (double-height void) glazing + mullions |
| `A-DOOR` / `A-DOOR-IDEN` | door blocks + tags `D1..` |
| `A-ROOF` / `A-ROOF-OTLN` | roof + outline (elevations / first-floor sheet) |
| `S-STRS` | stairs |
| `A-ANNO-*`, `G-ANNO-*`, `*-PATT` | dimensions/text/hatch — **ignore for geometry** |

## Window/door size codes

AU convention: **leading letters = type** (A awning, F fixed, S/X sliding-stacker; combos
like `AFA` = awning-fixed-awning), **4-digit group = Width then Height in 100 mm units**.
Examples: `AF0615` = 600w × 1500h, `FCM 2230` = 2200w × 3000h, `AFA3040` = 3000w × 4000h
(a feature/void window). Explicit door blocks give `WxH` directly (e.g. `870x2400`).

## Coordinate mapping into the model

DXF is plan-space **mm** at architect world coords. To place in the Three.js model
(metres, Y-up, X+=East, Z+=North/street/high): take DXF `(x, y)` mm → ÷1000 → metres,
map plan-X → model-X and plan-Y → model-Z per the **site-plan north arrow**
(`dxf/plan_site.dxf`), and set Y from the level table in `cad-metadata.json`. Verify
orientation against a known feature (garage door / a tagged window) before trusting it.
